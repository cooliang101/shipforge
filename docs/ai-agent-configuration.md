# AI Agent 部署配置接入指南

本指南供 AI Agent 阅读现有项目、整理新增或修改部署配置所需的信息。配置格式以 [配置规范](configuration-guide.md) 为准，交互步骤见 [TUI 使用指南](tui-guide.md)。当前没有 AI Agent CLI、MCP 或配置写入 API；`shipforge.exe` 启动 TUI，配置最终由 TUI 保存。

## 任务目标

把项目现有的构建与发布方式映射到 ShipForge，交付可直接填写的配置清单。沿用现有部署目录、启动脚本、服务和权限。只保留上一版应用压缩包用于失败回退，不接管数据库、附件或日志，不增加迁移流程。

“增加部署配置”默认只涉及配置整理与保存。构建测试、远端探测及实际发布按用户已授权的范围执行；配置保存与发布执行是两个独立动作。

## 读取项目

优先读取以下文件，并在配置清单中标明依据：

- 已有 `shipforge.yaml`：组件、环境、连接引用、固化目录及服务命令。
- 项目说明与现有发布脚本：实际构建步骤、上传文件、远端目录、启停方式。
- `package.json`、`go.mod`、`Cargo.toml` 等：构建入口与输出位置。
- 已提供的服务配置或启动脚本：程序名称、工作目录、参数与可用的只读检查。

只询问无法从这些资料确定的值。无法确认的构建命令、端口或服务名标为待确认，不用常见默认值代替事实。不读取或输出密码、私钥内容及运行数据。

## 整理配置项

| 项目 | 如何确定 |
| --- | --- |
| Project 根目录与名称 | 使用实际项目根目录；已有项目沿用其身份 |
| Component | 按可独立构建与发布的应用划分，例如后端程序、前端静态站点 |
| 构建工作目录 | 相对项目根目录；省略时默认为组件同名目录，项目根目录应明确填 `.` |
| `build` | 按顺序列出程序和独立参数，例如 `[npm, run, build]`；沿用已有构建方式 |
| `artifact` | 相对构建工作目录的单个文件或目录，例如 `build/server` 或 `dist` |
| Environment | 使用用户要求的环境，已有环境保留身份 |
| 连接 | 选择 TUI 中已保存的 `用户@主机:端口`；同一连接可分配给多个组件 |
| `root` | 服务器上原有应用目录，填写已核实的绝对路径 |
| 服务命令 | 每个环境、每个组件分别配置启动、更新、恢复、停止；静态站点可不配置 |
| 检查 | 现有 systemd 检查、只读命令或健康 URL；没有可靠检查时明确说明 |
| `after` | 仅有实际发布顺序要求时填写；不会自动选中或部署依赖组件 |

构建在本机执行，服务命令在远端 `root` 中执行。Windows 上构建 Linux 程序时，复用项目已有的 Linux 构建脚本或已验证的交叉编译方式，不把 Windows 可执行文件当作 Linux 产物。

`artifact` 是构建输出，不是事先压缩的发布包。文件产物按原文件名发布；目录产物发布其内容。输出必须只包含应用文件，不能把混有数据库、上传附件或日志的项目根目录作为产物。ShipForge 自行生成 Release 和上一版应用压缩包。

## 服务与密码连接

命令使用独立 argv，不把 `cd ... && ...` 写成一条程序名，也不额外增加 Shell 字符串格式。项目已有脚本可通过解释器和脚本路径调用；随应用发布的脚本需包含在产物中，既有服务器脚本则保留原位置。

systemd 使用完整 unit 名。账号已有 sudo 权限、SSH 与 sudo 使用同一密码时，可在服务动作编辑页按 `p` 使用保存密码，命令示例为：

```text
启动/更新：[/usr/bin/sudo, -S, --, /usr/bin/systemctl, restart, --, aigenvideo.service]
停止：    [/usr/bin/sudo, -S, --, /usr/bin/systemctl, stop, --, aigenvideo.service]
```

这些路径和 unit 仅是示例，采用前须有项目或服务器信息支持。`update` 省略时复用 `start`，`restore` 省略时复用有效的更新命令；若原程序需要不同的恢复动作，应明确配置。不要为了接入而改 sudoers、增加权限或改造服务文件。

已有密码连接直接复用。新建连接由用户在 TUI 按 `F5` 输入遮蔽密码，核对 Host Key 后才认证和保存。不要让用户把密码发到聊天，也不要将密码放进命令参数、项目 YAML 或文档。标准 password 登录不等于 keyboard-interactive/MFA 支持。

HTTP 健康检查由服务器发起，仅接受 2xx。登录接口的 401/403 不能当作健康检查通过；优先使用项目实际提供的健康端点或已有只读服务检查。

## 在 TUI 中保存

1. 启动 ShipForge，在项目列表选择目录。已有配置进入概览，新项目进入首次设置；无需先切换命令行工作目录。`F6` 可切换简体中文。
2. 已有项目按 `e` 编辑草稿；按 `c` 管理组件，填写工作目录、构建 argv 和产物路径。
3. 按 `e` 管理环境，选择该环境需要的组件，为每个组件选择已保存连接、填写原部署目录及服务与检查。没有所需连接时，从项目页的连接管理入口添加。
4. 逐层应用表单，返回编辑主页，按 `p` 查看完整 YAML，核对后按普通 `c` 保存。首次设置同样需完成连接分配和最终 YAML 预览确认。
5. 保存后重新打开配置核对；只有用户要求测试或发布时，才从概览按 `d` 进入部署选择与预检，检查计划后再执行。

Agent 有可用的交互终端能力时，可在用户授权范围内操作上述流程。没有交互能力时，交付下面的填写清单，并准确说明“尚未保存”，不改用直接写 YAML 的方式绕过配置编辑器。

`_shipforge`、Project/Environment ID、Destination ID、revision 和 generation 由程序维护。不要生成假 ID、复制其他项目的系统区或写用户级连接/凭据注册表。配置缺少或损坏系统区时，报告实际问题，不把原项目偷偷重新初始化为新身份。

## 示例：aiagent 的接入清单

以下目标来自已确认的部署需求；构建细节仍应读取该项目现有脚本，不能凭本表推断。

| 配置项 | server | website |
| --- | --- | --- |
| 项目根目录 | `D:/project/aiagent` | 同左 |
| 环境 | `production` | `production` |
| 已保存连接端点 | `tomato@10.0.0.206:22` | 复用同一连接 |
| 远端目录 | `/home/tomato/aigenvideo/server` | `/home/tomato/aigenvideo/website` |
| 产物范围 | 原 Linux 后端程序，保持 `aigenvideo_server_linux` 文件名 | 原前端构建输出中的静态文件 |
| 服务 | 沿用 `aigenvideo.service` 与现有启动方式 | 沿用现有静态站点服务；无需停止时不配置服务动作 |
| 本地构建工作目录、argv、artifact 相对路径 | 从已有发布脚本确认后填写 | 从已有发布脚本确认后填写 |

这里 `~` 已按确认的远端用户展开，不能将本机用户目录作为远端目录。不要移动应用目录、重新生成 Nginx/systemd 配置，或增加数据库和附件备份。

## Agent 交付模板

```text
项目：
环境：

组件：
依据文件：
构建工作目录：
构建 argv（按顺序）：
artifact（相对工作目录）：
已保存连接端点：
远端 root：
启动 / 更新 / 恢复 / 停止 argv：
只读检查 / 健康 URL：
after（如有）：

待确认项：
当前状态：仅整理清单 / 已保存配置 / 预检通过 / 已实际发布
验证依据：
```

每个组件填写一份。验证依据应区分读取脚本、保存成功、构建成功、预检成功与实际服务检查结果，不把其中一个阶段的成功说成全部部署完成。
