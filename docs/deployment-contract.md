# 部署助手职责

2026-09-07 用户明确修正产品定位。本文取代旧文档中强制版本目录、current 软链接、空目录接管和多版本管理的要求。

ShipForge 兼容应用现有的发布方式，不改造应用的运行方式。流程只有：构建产物、上传校验、把上一版应用保存为一个压缩包、发布到既有目录、执行用户配置的启停命令、验证；确认发布失败时用上一版应用压缩包恢复并执行恢复命令。

- 不要求迁移目录、使用 releases/current、修改 systemd/Nginx 配置或改变应用工作目录。
- 不新增权限、不改 sudoers；需要 sudo 时使用账号已有权限。
- 不备份、迁移、恢复数据库、附件、日志或其他运行数据。应用包之外的已有文件保持原样。
- 上一版压缩包仅用于本次应用发布失败回退，不扩展为备份管理或多版本保留系统。
- 发布范围以构建产物为准，不能打包整个混有运行数据的目录，也不能递归删除整个部署目录。首次接入时明确上一版应用文件范围。
- 保留必要的传输校验、路径校验、操作记录和结果判断。服务命令结果未知时先查明结果，不能重复启停或盲目覆盖。
- 不声称覆盖文件具有原子切换性质，不替应用处理数据一致性。

## 实现状态

现有 SSH 驱动仍实现 releases/current 和远端标记，不支持上述原目录覆盖发布。这属于待替换的旧实现，不能通过要求用户迁移来绕过，也不能直接删除非空目录保护就宣称支持。

本次 aiagent 现场的目录迁移、附加 systemd 配置和 Nginx root 改造已撤销；数据库和附件备份已清除。原目录和旧服务恢复正常，只保留上一版后端程序及用户端静态产物压缩包。尚未用新发布流程上线业务新版本。
