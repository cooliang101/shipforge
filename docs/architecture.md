# ShipForge Architecture

当前发布协议见 [部署助手职责](deployment-contract.md)，配置见 [configuration-guide.md](configuration-guide.md)。2026-09-07 原目录发布完整替换旧版本目录协议；旧方案仅保留在 Git 历史和历史验收文档中。

## 边界

`domain` 保存稳定身份、版本和状态；`application` 编排构建、产物、发布、失败恢复与本地历史；`drivers/linux_ssh` 处理固定 Host Key 的 SSH/SFTP、原目录文件发布及用户配置的服务命令。TUI 只负责输入、状态和绘制；配置、项目注册表、凭据、SQLite 历史和日志各有独立边界。

Release 是唯一版本化 tar.gz 产物，内含 manifest。artifact 是构建输出，不是备份对象。无用户可选 Driver 或发布模式；不要求迁移服务、改写启动配置或安装服务器依赖。

## 原目录发布

1. 只读预检连接、目标、已确认的当前应用状态、空间和配置的命令工具。
2. 本地构建并打包；每个 Component 单独冻结身份、目标、服务命令和产物摘要。
3. 在 `root/.shipforge-deploy/incoming.tar.gz` 独占上传，校验大小、SHA-256、manifest、路径与条目类型。
4. 应用范围为包内顶层条目与已有应用范围的并集。记录原应用快照，压缩为唯一的 `previous.tar.gz`。不遍历范围之外的运行数据。
5. 执行已有 stop 命令，在原 root 逐文件写入临时文件再替换目标，删除旧应用范围内失效的应用文件。
6. 在原 root 执行 start/update 及配置的只读检查，记录稳定状态并移除 incoming 包。
7. 明确失败且状态可验证时，恢复上一版应用文件、移除本次新文件，执行冻结的 restore 命令并检查。没有原应用时停止服务。

无 current 链接、版本目录切换、远端多版本保留、远端审计备份或数据库迁移。`previous.tar.gz` 只用于应用回退；不会保留整个部署根目录副本。配置变化不会触发 systemd、Nginx 或权限策略改造。

## 安全与结果

- 固定 Host Key 校验先于密码解密/认证。密码只保存在 Windows 当前用户 DPAPI 密文中，不进入 YAML、argv、历史或日志。
- 命令保存为独立 argv，工作目录独立引用，Shell 边界进行引用。密码 sudo 只对显式规范 `sudo -S --` 使用保存的登录密码，响应专用提示一次，不修改 sudoers。
- 包路径拒绝绝对路径、遍历、元数据目录、链接、特殊条目与权限提升位；已有应用文件拒绝链接/特殊文件。覆盖前后检查应用摘要，漂移不会被当作删除授权。
- 使用状态记录区分上传、准备、压缩、覆盖、服务执行、恢复和稳定状态。服务命令发出前先记录 pending；无退出状态、超时、断连或中断导致结果未知时阻止竞争恢复。
- 取消前未发出的操作不执行；已知结果使用独立恢复令牌完成必要收尾。只丢弃同一操作仍未应用的上传，不丢弃已应用/未知现场。
- 文件替换不是全目录原子切换，不负责应用数据一致性。发布范围内避免并发写入；不承诺抵御同权限恶意服务器进程的目录替换竞态。

## 历史、恢复与兼容

本地 SQLite 记录计划、冻结的身份/连接修订/目标/服务命令、操作意图、产物摘要、结果和观察。操作意图持久化失败时不继续新的已知写入；远端效果后的历史失败保留内存结果和告警。结果未知不能解释为没有执行。

历史恢复不得以当前配置补造缺失命令；只允许已保存证据与远端上一版应用相符的恢复。旧 releases/current 能力引用不能送入新协议执行，旧文件和记录不自动迁移或清理。Driver-neutral 旧能力类型继续支持读取历史，内置 SSH 不再提供 Retention 能力。

## TUI 生命周期

Ratatui/crossterm 使用缓冲绘制、有限内存窗口。工作线程保留取消令牌和 join 所有权；事件工作保留请求 ID，直接轮询任务仅持有一次。导航/退出前等待任务结束，取消的读取或计划不能打开确认页。已知写入结果不能因晚到取消而丢失。退出、错误和可捕获 panic 恢复 raw mode、备用屏幕与光标，无 detach。

测试与实际部署记录见 [inplace-deployment.md](validation/inplace-deployment.md)。
