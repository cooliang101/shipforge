# TUI 使用指南

启动 `cargo run` 或 ShipForge 可执行文件。所有部署操作均在 TUI 中完成，没有部署子命令。顶部固定显示当前页面、项目和环境，适用时带 Component；底部快捷键与操作消息分行显示。确认页面只接受无修饰键的确认操作。

## 帮助与候选搜索

`F1` 打开当前页面帮助，`Esc` 关闭；帮助打开时不会把确认键传给下面的页面。支持候选选择的页面用 `F4` 搜索，输入文字过滤，方向键选择，`Enter` 聚焦候选，`Esc` 放弃搜索。搜索不会启动连接、部署或保存；选择 SSH Host 会填入连接草稿，选择 Environment 会切换环境。历史 Environment ID 选择页只搜索当前已加载页；历史发布记录和报告列表尚不支持搜索，日志使用下面的专用 `/` 搜索。

列表用反显、粗体和 `>` 标识当前项，不只依靠颜色。建议至少使用 80×10 的终端；远端目标选择页低于此尺寸会提示调整窗口。读取失败、加载中和没有候选分别显示，失败不代表空列表或未部署。

## 项目与配置

从项目列表选择目录；已有有效 `shipforge.yaml` 时直接打开概览，文件不存在则进入新项目设置。项目列表的 `x` 只从最近列表移除登记，不删除项目、配置、历史或远端内容。

最近项目读取失败时显示固定警告，旧缓存不可打开；`f` 重试，`o` 浏览目录。不会自动覆盖损坏的注册表。选择有效项目后的登记若仍失败，应先处理本机注册表问题再重试。

首次设置用空格勾选 Component；发现失败或没有候选时可重试，或按 `a` 手动添加。手动表单分别填写名称、工作目录、`artifact` 和程序/参数，工作目录预填 `.` 表示项目根目录；表单预览的 `c` 仅加入草稿，不执行构建或写 YAML。

连接分配页用左右键切换 Component、上下键选择连接、空格或回车分配；`a` 新建 SSH，`e` 编辑当前 Component 的部署目录与服务，`n` 预览 YAML。最终无修饰 `c` 才保存项目配置；配置保存本身不会部署。

项目概览中：

| 按键 | 操作 |
| --- | --- |
| 左右键 | 切换 Environment |
| 上下键 / `PgUp` / `PgDn` / `Home` | 滚动目标信息 / 返回顶部 |
| `d` | 选择 Environment/Component，检查并预览部署 |
| `e` | 编辑配置草稿 |
| `m` | 历史、Release、回滚及检查报告 |
| `Esc` | 返回项目列表 |

概览、部署选择和管理页沿用同一个环境选择，仅在当前会话按 Project/Environment ID 记忆；同一 ID 改名仍保留选择，同名新建环境或不同项目不继承旧范围，不新增 YAML 字段。部署只处理勾选的 Component；没有选择时不能进入检查。

环境名包含 `prod`（不区分 ASCII 大小写）时，顶部及确认页显示 `[PRODUCTION]`；滚动计划不会移走顶部提示。这只是名称提示，不是环境分类或安全保证，没有标记也必须核对服务器。部署与回滚都先检查、预览，再按 `c` 执行，回车不代替执行确认。

概览和选择页的连接端点、revision 与系统 ID 来自本地登记，不表示服务器在线、服务健康或已部署；刷新失败显示未知，不继续显示旧端点。ID 仅用于区分连接，不要求手填或增加别名。执行仍以检查后的计划及重新验证为准。

编辑页用 `n` 修改项目名、`c` 管理 Component、`e` 管理 Environment。Component 列表的 `f` 重新发现构建候选，`a` 手动新增；Environment 中用空格选择实际需要的 Component，回车编辑其连接、root、service、health 和 `after`。已有连接从列表选择，不填写 Destination ID。

构建命令按顺序保存为程序与参数数组：每个参数单独编辑，空格属于该参数，不被解释成 Shell。`artifact` 相对于 Component 工作目录；新增 Component 未填写工作目录时默认为同名子目录。删除或新增只是修改草稿，不操作服务器。

逐层选择“Apply”把表单加入草稿，再在编辑首页按 `p` 查看完整 YAML；只有预览页的 `c` 才原子保存。`Esc` 取消当前字段/表单或返回；离开有未保存草稿的编辑器需再次确认丢弃。保存前如检测到原文件或连接变化，会要求重新加载。保存期间避免其他编辑器同时写入。

Project/Environment 改名保留 ID 和固化 root。Component 换名需显式删除旧项并新增，不继承旧 Release。已有目标清空 root 输入表示保留原固化 root，新目标才生成默认 root。完整规则见 [配置指南](configuration-guide.md)。

## SSH 连接

项目列表按 `c` 打开独立连接管理，不必先创建 Project。`a` 新建，选择连接后回车看详情：`e` 修改、`v` 只读验证、`x` 申请移除。

首次设置与独立连接表单使用相同按键：Tab 切换字段，`F2` 切换 SSH config 候选，`F3` 浏览私钥；也可选择已保存身份或 SSH Agent。回车获取 Host Key，核对指纹后只按无修饰键的 `y`，回车不会信任指纹；认证成功才保存。修改生成新 revision 并保留旧记录，不自动更新已部署服务。

密码登录按 `F5`，直接输入密码（固定遮蔽显示）；Backspace 删尾、Delete 清空。回车获取指纹，再按 `y` 确认并认证。密码以 Windows 当前用户保护的密文保存，重新启动可复用；修改密码也从 `F5` 进入。不会将明文密码写入项目配置、命令行或日志。连接编辑时选中已有密码身份表示继续复用，按 `F5` 则创建新密码草稿；取消不会覆盖旧密码。只支持标准 SSH password，不包含交互式 MFA。

私钥浏览器用回车进入目录、Backspace 返回上级、`s` 选择文件。首次设置的身份读取、指纹获取和认证在后台执行；`Esc`/`Ctrl+C` 请求取消后，等待任务结束再返回。连接保存早于项目 YAML 的最终确认；之后取消项目或目标草稿，不撤销已经确认保存的连接。

仍被已登记项目或历史记录引用的连接不能移除；引用无法完整检查时也不移除。连接移除不会删除凭据文件或远端数据。凭据配置异常时检查用户级连接/身份，不把密钥写进项目 YAML。

密码模式以独立的紧凑表单显示 Host、User、Port 和 Password，底部只保留输入、清空、继续和取消操作；SSH Agent 与候选主机的发现提示不出现在密码输入区。首次设置与连接编辑使用相同布局。

## 选择部署目录与服务

服务选择包含不管理服务、systemd 预设和自定义命令；配置只属于当前 Environment/Component，不属于 SSH 连接。systemd 候选自动填充 start/stop 与稳定性检查，按 `c` 可查看或修改统一命令计划。自定义服务不隐式运行 systemd。

首次设置的连接分配页按 `e`，或项目编辑器的目标表单按 `b`，打开当前 Component 的远端目标选择：

| 按键 | 操作 |
| --- | --- |
| `r` / `m` | 手动修改根路径 / 可选 `.service` 名称 |
| `c` | 编辑当前服务的分阶段程序与参数 |
| `v` | 只读探测当前根路径与 systemd 候选 |
| `b` | 从远端 `/` 开始浏览目录 |
| 目录页回车 / Backspace | 进入高亮子目录 / 返回上级 |
| 目录页 `g` / `f` | 输入路径 / 刷新或重试 |
| 目录页 `s` | 选择顶部显示的当前目录，不是高亮子目录 |
| 服务页回车 / `Esc` | 应用目标草稿 / 放弃此次目标修改 |

`/` 只供浏览，不能作为部署 root。目录浏览只读取直接子目录，不递归扫描、不创建目录或修改服务；失败或取消后保持“内容未知”，可重试或改路径。目录可读、曾可写或列出了服务，都不表示部署预检或健康检查已通过。

根路径与服务只属于当前 Environment/Component，同用一个 SSH 连接的组件仍分别配置。可选择不管理服务，手动服务名留空含义相同。项目编辑器返回后仍需 Apply 目标、Apply Environment，再从首页预览并确认 YAML；探测与选择不会直接保存。

自定义编辑器先选择首次启动、更新、恢复、停止或只读检查；`Enter` 查看命令列表，`a` 新增程序、`Enter` 逐参数编辑，参数页 `a` 追加一个参数、`d` 删除参数。空格留在当前参数中，不解释为 Shell。文本页 `Home`/`End` 和左右键查看长值，Backspace 删尾、Delete 清空，Enter 应用，Esc 丢弃该字段。动作页 `d` 删除命令，阶段页 `x` 清空动作或检查。

start/stop 必须填写；更新留空复用 start，恢复留空复用有效 update。最后选择 Apply 加入目标草稿，仍需逐层 Apply 和 YAML 预览确认。`Esc` 退出服务编辑器丢弃本轮服务草稿，不写文件；从 systemd 进入时保留原稳定检查，除非显式清除或提交自定义检查。

schema 1 项目打开时进入转换编辑器，按 `p` 核对完整 schema 2 YAML、`c` 保存后才能部署。等价转换保留身份与 generation；不是重新初始化。新历史保存命令快照，旧服务历史缺少快照时回滚不可用，不能用当前命令冒充历史配置。

部署计划会展示实际生效的阶段命令、版本工作目录和检查规则。PM2 应明确更新实际程序路径，不能只重启旧名称。若服务命令没有已知退出结果，界面要求人工核实，不自动再发恢复命令；日志中的失败命令诊断 JSON 包含实际工作目录。

服务命令和命令检查返回已知结果后，其 stdout/stderr 进入现有脱敏日志，每个流最多保留 64 KiB，超限明确提示；不是逐字节实时输出。超时或断线没有已知结果时，仅保留失败诊断，不承诺完整命令输出。内部文件/凭据探测输出不因此写入普通日志。

## 系统维护区重新初始化

`shipforge.yaml` 存在但 `_shipforge` 缺失或损坏时，不自动修复或连接远端。提示页按回车或 `r` 生成预览；只有用户配置、连接引用与路径能安全校验时才继续。预览包含将写入的完整 YAML 和新身份，按上下键/PgUp/PgDn/Home/End 纵向滚动，左右键或 `[`/`]` 横向查看长行，`0` 返回行首。

无修饰 `c` 确认以新 Project/Environment 身份保存，`Esc` 取消。原文件或连接记录变化会使预览失效；可靠的原 root 保留，无法确定时拒绝猜测。不会恢复旧身份、历史或接管远端目录。YAML 已保存但最近列表登记失败时，会保留保存成功的提示，并明确显示登记失败。

## 历史、Release 与回滚

管理首页用左右键切换 Environment：`h` 查看本地历史，`i` 选择 Component 并读取远端库存，`p` 查看保存的检查报告。打开历史或报告不会自动连接服务器；缺失数据库不因浏览而创建。

已删除 Environment 的记录从管理首页 `a` 进入：选择历史环境 ID，再以 `h` 查看历史/日志、`p` 查看报告。列表按真实 ID 区分同名新旧环境，不推测旧名称或重建配置；只有报告、没有发布记录的环境也能查看。此范围始终只读，不能发起远端检查或回滚；`Esc` 逐层返回原 ID 列表，再返回当前环境管理。

历史/报告列表用 `n`、`b` 翻页，`f` 刷新，回车打开详情；`Esc` 返回原页码及选中记录。同页刷新优先保留相同 ID 的焦点，不按同名猜测。列表先显示结果、时间和待核实数量，完整 ID 另起一行；上下键、`PgUp`/`PgDn`、`Home`/`End` 选择记录。

历史详情显示创建时间、最后本地更新时间、Git 信息、原始目标、包摘要、准备回执、步骤、观察和未完成意图。创建时间不是执行开始时间，更新时间不证明执行结束，历史 `running` 不证明进程仍在运行。详情用上下键/PgUp/PgDn/Home/End 纵向滚动；`[`/`]` 每次横移 32 个字符簇，`,`/`.` 每次微调一个字符簇，`0` 返回行首。长路径和诊断可横向查看；视口不会因超过 65,535 行而隐藏末尾。

`l` 打开本地日志查看器。它一次扫描仍保留的全部轮转文件，再对结果分页，不需要手动选择轮转文件。丢失的本地日志无法从远端恢复。

在历史详情按 `r` 回滚：

1. 用空格选择要回滚的 Component，回车读取可用目标；默认不选中任何组件。
2. 左右键选择版本，再用空格确认该组件；`d` 查看完整目标、路径及不可用原因，`Esc` 返回并保留选择。
3. 回车只进行远端检查，随后核对目标服务器、root、当前版本、目标版本与执行顺序。
4. 按 `c` 执行；回车或组合键不代替确认。预览页的 `Esc` 返回原 Component/版本选择，不执行回滚。实际执行后，返回路径不再保留可重复确认的旧计划；再次回滚必须重新检查。

回滚只处理所选子集，并建立关联原部署的新记录。旧 generation、缺失历史修订、缺少包或健康证据不能借用当前配置绕过；`not_deployed` 仅在有相应历史证据时可选。

从历史发布发起检查时，展示其冻结的 Destination revision、generation 和端点指纹，不用当前连接补充旧目标。缺少目标快照的记录仍可浏览，但不提供检查或回滚入口。

## 步骤与日志

执行中、完成页或历史详情按 `l` 查看日志。回滚执行失败后也可进入本次回滚的日志，不会误用作为回滚来源的旧 Deployment。尚未获得实际 Deployment ID 时明确等待，不推断 ID。

| 按键 | 操作 |
| --- | --- |
| 上下键 / `PgUp` / `PgDn` | 选择日志记录；详情中滚动全文 |
| `Enter` / `p` | 查看完整选中记录 / 全部已有步骤、耗时及覆盖范围 |
| 空格 / `Home` / `End` | 暂停或恢复实时跟随 / 第一条 / 最新条 |
| `/` | 输入最多 128 字符，搜索全部仍保留的本地日志 |
| `f` / `t` | 选择 Component / 步骤筛选，可选全部 |
| `h` 或 `r` / `n` / `b` | 重新读取保留日志 / 下一页 / 上一页 |
| `v` | 返回同一次操作的实时窗口并清除筛选 |
| `y` | 请求复制选中记录中已保存、已脱敏的失败命令 argv |
| `e` / `s` | 导出全部匹配日志 / 整次部署的本地记录摘要 |
| `F1` / `Esc` | 查看完整帮助、范围与当前消息 / 返回 |

文本搜索不区分大小写，按字面量匹配脱敏正文、来源、步骤和实际失败命令参数，不执行正则或命令。Component 与步骤筛选同时生效；实时页的 `f`/`t` 只筛选当前窗口，`h` 或 `/` 才扫描保留文件。步骤候选来自实际记录，不从日志正文猜测。旧文本日志没有可信步骤、耗时或失败命令，不伪造这些字段。

实时日志只保留有界窗口，丢弃条数与生产端遗漏分别提示。步骤状态和持久化状态独立显示；已知执行成功但记录失败，不改报为执行失败。运行耗时使用单调时钟，在执行线程完成时冻结；历史缺少起止时间时显示未知。搜索完整性只针对仍保留的文件，不代表操作全部原始输出。文件丢失、损坏、缺片、正在轮转或超限均明确提示；需要时重新读取，不能将读取失败当作零匹配。

复制内容是诊断用 JSON（程序和参数数组），不是可直接粘贴执行的 Shell。只复制当时记录的失败命令，不从当前 YAML 重建；没有快照则提示不可用。终端必须允许 OSC 52，发送成功不证明剪贴板已更新，请粘贴核对；不支持时使用导出。

导出只读取本地记录：`e` 包含全部保留文件中匹配当前筛选的内容及覆盖声明，`s` 不受日志筛选影响，也不是新的健康检查。选择已有目录后按 `s`，检查自动文件名与完整预览；`n`/`b` 切换正文块，上下键翻读块内内容，`F1` 查看完整路径及说明。仅无修饰 `c` 写入预览中的准确文本；`Esc` 放弃，不覆盖已有文件。日志与摘要导出各限 8 MiB，超限明确拒绝。Unix 文件为 `0600`，Windows 继承目标目录权限，请选私有目录；目录无法安全检查时拒绝写入。

日志后台读取/导出期间，`Esc` 请求取消并等待该线程结束，不脱离任务；`Ctrl+C` 同时请求活动部署或回滚安全取消。打开或关闭空闲日志页不会取消部署。

## 安全退出与终端中断

空闲顶层页面按 `q` 直接退出。存在部署规划/执行、管理读写、连接、项目编辑、重新初始化、远端选择、SSH 设置或本地日志任务时，`q` 只打开退出确认，不取消任务：

- `Esc` 或 `r` 关闭确认并返回当前任务；
- `c` 或 `Ctrl+C` 请求取消全部受跟踪任务并进入等待页；此后不能继续操作，也不会后台脱离；
- 等待会持续到线程结束；部署或回滚还须到达补偿/恢复安全边界，不能用第二次按键强制跳过。

帮助、候选搜索或日志覆盖层打开时，普通 `q` 先由覆盖层处理，不会意外打开退出确认。raw mode 下在普通任务页按 `Ctrl+C` 只请求该活动任务安全取消并留在界面；在退出确认页按它才表示取消后退出。操作系统发出的 `INT`、`TERM`、`HUP` 或受支持的 Windows 控制事件则直接进入安全退出。

正常退出、终端 I/O 错误和可捕获 panic 都会逐项尝试关闭 raw mode、离开 alternate screen 并显示光标；只有错误和 panic 会在恢复后输出固定、脱敏的诊断。`SIGKILL`、OOM、`panic=abort` 或宿主强制终止无法被程序恢复；下次启动应查看待核实记录。若底层系统调用永久不返回，安全退出也会继续等待而不会假装任务已经结束。

## 不确定状态与取消

检查报告区分目标版本、原版本、其他版本、确认未部署和未知。管理页的 `i` 是库存/对账读取，不是部署向导中的环境预检；它不执行工具能力或服务健康检查。库存或 current 一致不代表服务健康，也不改写原部署结果、补完旧意图或重放命令。无数据库时，显式检查可保存库存缓存，但不重建配置或丢失历史。

报告顶部明确“已保存”或“保存未确认”；保存出现警告时仍可在本页查看已获得的事实，并核对已保存报告，不把保存未确认当作没有观察结果。审计逐条显示阶段、结果、关联 Deployment 和观察，临时残留显示类型及可识别的关联 ID；这些证据不证明整体成功、远端所有权或删除许可。空记录不等于不存在。

管理读取或检查失败后进入独立错误页，不将旧列表伪装为新结果。允许安全重试的读取/计划检查用 `f`；返回旧页会保留快照提示，只有成功刷新/检查才清除。远端库存检查失败不直接提供重复执行按钮，应先核对已保存报告与结果，再明确发起新检查。

管理后台操作期间，`Esc`/`Ctrl+C` 请求取消，界面等待确定结果或安全恢复边界，不脱离运行。取消的本地读取、回滚候选与计划即使迟到成功，也不进入新的确认页；库存检查和实际执行则保留已得到的报告及结果，并提示曾请求取消。回滚结果按真实成功/失败/取消状态显示，警告数与人工恢复数量置于首行；主失败、补偿结果和持久化警告分别呈现。失败或持久化警告出现时，保留 Deployment ID，先检查历史和远端事实，不盲目重试。

步骤元数据使用可读名称，例如 `Uploading`、`Packaging`，不显示 Driver 命名空间或能力标识符；用户日志正文不会被步骤名称转换改写。部署控制错误提供安全的处理建议，保留已知结果及持久化警告，不直接展示底层解析器、数据库或 Driver 的原始错误字符串。
