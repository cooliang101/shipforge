# TUI-01：统一导航与部署确认验收

日期：2026-09-04。状态：TUI-01 通过自动化工作包验收；M3 其余工作包、M4 和完整 MVP 尚未完成。

## 实施范围

- 概览、部署选择和管理页按 Project/Environment 稳定 ID 共享当前会话的环境选择；同 ID 改名保留，同名重建或其他项目不继承。历史只读范围不替换当前选择，不写 YAML 偏好。
- 固定上下文行显示项目、环境及页面；长目标/计划正文可滚动，生产环境名称提示保持可见。部署和回滚保留显式确认，未勾选 Component 不提示可执行检查。运行中和结果页保留实际执行环境；取消帮助与会话真实状态一致。
- 当前连接显示端点、revision 和系统 ID；读取本地有界列表，不访问凭据或 SSH。失败刷新清空旧标签并显示未知。历史检查保留冻结引用，不借用当前连接。IPv6 方括号只改变显示，不改变设置或指纹。
- 首次设置和连接管理统一 `F3` 私钥选择与无修饰 `y` 指纹确认，Enter 不确认信任。步骤与能力元数据转换为可读名称，不改写用户日志正文、名称或版本。
- 部署控制错误按类型提供建议，不回显解析器、SQLite、进程或 Driver 原始错误字段。保留 Deployment ID、已知逐 Component 结果、未知状态及持久化/日志警告；错误不被误报为副作用尚未发生。

没有新增配置形式、别名、用户输入 ID、数据库迁移、锁或远端协议。没有改动 Driver 的部署、传输或补偿行为；应用层非界面改动仅涉及端点显示和错误措辞。

## 审查与回归

导航/执行上下文、管理/历史范围、连接/编辑渲染和公共展示函数由不同实现者交叉审查，再进行集成范围核对。审查发现并修复：边界方向键重选全部 Component、活动会话被通用底栏覆盖、长内容遮住生产提示、缺失历史快照仍展示不可用操作、同端点连接难以区分，以及原始 Driver target 即使语法合法仍可能泄密。

| 证据位置 | 覆盖内容 |
| --- | --- |
| `src/tui/app/navigation/tests.rs` | 10 项跨页/改名/重建范围测试，本地缓存失败不沿用旧端点，真实规划网关的无泄露错误，固定上下文、长列表、空选择、边界方向键及真实会话取消底栏 |
| `src/tui/presentation.rs` 测试 | 9 项 Unicode/控制符/长度边界、生产名称提示、IPv6、上下文排序、已知元数据翻译及用户内容保留 |
| `src/tui/deployment_error.rs` 测试 | 6 项嵌套执行 ID/持久化/日志警告、可读操作名、受控 Driver 建议、合法但不可信 target、解析/数据库/进程秘密哨兵、执行后未知副作用 |
| `src/tui/app/{management,connections,project_edit}/` 测试 | 已删除环境只读范围、冻结历史目标、生产回滚确认、80 列帮助、编辑/后台上下文、同端点 ID、无效操作与指纹确认 |
| `src/config/destinations.rs` 测试 | DNS、IPv4、裸 IPv6 和带方括号 IPv6 显示；序列化设置和端点指纹不变 |

使用 Ratatui `TestBackend` 和键盘事件，包括 80×10 等受限视口；回滚路径复用 Fake Driver、真实密封计划及 SQLite，缓存与配置错误使用隔离临时文件。没有连接已保存的真实项目或生产目标。测试定位与运行方式见 [测试指南](../../tests/README.md)。

## 最终门禁

冻结源码使用 Rust/Cargo 1.96.1。Windows 原生执行；Linux 在 WSL Ubuntu-22.04 使用既有隔离工具链和 target，不修改默认工具链。两端均执行：

```sh
cargo test --locked --all-targets --all-features --quiet
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo build --locked --release
```

| 门禁 | Windows | Linux |

| 库测试 | 634 通过 | 646 通过 |
| SSH/SFTP 协议测试 | 8 通过 | 8 通过 |
| 中断恢复父用例 | 1 通过（内部 15 个场景） | 1 通过（内部 15 个场景） |
| fmt / 严格 Clippy / release | 全部通过 | 全部通过 |

默认套件各有 8 项 ignored：6 项外部 SSH/systemd 用例、1 项独立连接诊断、1 项由父用例显式启动的中断子进程助手；未将忽略用例计入通过。Windows `cargo audit` 退出码为 0，仍报告已有 `wnaf 0.14.0` 被撤回警告；本工作包未改依赖。

## 边界与后续

本次没有重跑外部 OpenSSH/systemd 部署验收；既有证据见 [M1](systemd-acceptance.md) 和 [M2](tui-mgt-01.md)，本次默认协议测试不替代真实服务验收。M2 早期 SSH 连接超时及另一次 unknown current 的根因仍未知，也未证明同源；后续复跑和百次连接基线不等于修复，继续由 `QA-01` 复核发行条件。

`[PRODUCTION]` 仅由环境名包含 `prod` 推导，不是安全分类；本地标签不是连通性、健康或操作授权。公共展示文本过滤不是秘密脱敏，也不重写既有日志或历史。自动化渲染不等于人工终端体验或完整退出恢复验证。

`TUI-02` 继续候选搜索、空/加载/错误状态、无障碍和损坏 `_shipforge` 确认重新初始化入口；日志搜索/复制/导出、页面一致性、退出加固及压力验证分别留在 `TUI-03` 至 `TUI-06`。当前阶段不宣称完整 MVP 或生产发布就绪。
