# RET-01：Release 保留与精确清理验收

日期：2026-09-04。范围：M2 的 RET-01 工作包。代码、独立审查、双平台质量门禁及三种真实 Linux 用例通过，不代表完整 M2 或 MVP 已完成。

## 实施范围

- 所选 Component 全部成功且结果落盘后，自动保留最新 5 个 Release，额外保护 current、同端点上一健康版本和未结束/待核实操作引用。计划预览说明清理，无新增 YAML 字段、表单、后台任务或锁。
- SQLite 在一个短事务内读取有界原始包、健康和引用证据；历史修订不改写，数据库丢失后的库存缓存不构成删除授权。逐候选复读保护集并先写入新意图。
- Driver 只接收准确候选，刷新库存并校验 current、原始包摘要、Marker、路径与挂载；先删除版本目录，再删除对应压缩包，不更改服务、current、审计或临时文件。
- 部分结果区分压缩包与目录的存在/缺失/未知。未知保留 pending 意图；清理失败、取消或结果保存失败停止后续清理，不撤销成功部署。

## 审查修正

应用、SQLite、Driver、测试夹具和文档分别实施并交叉审查。修复并回归了元数据命令替换吞掉 NUL/尾部换行、截断目录列表恰好以换行结束、原始包被错误归入回滚记录、写入意图耗尽安全时间预算等边界。删除脚本改用完整字节摘要和固定描述符；意图落盘后再次检查取消与剩余预算，已开始的调用保留完整 180 秒期限。

Linux 协议夹具原先在 180.01 秒超时。固定服务端设置及测试范围，仅开启生产客户端 TCP `nodelay` 后，完整用例在 4.16 秒通过（5,668 次 exec 请求）；未增加期限或减少断言。阶段日志只含固定名称、累计毫秒和命令计数。另修复连接间共享 channel 映射的问题，并用无网络测试验证连接隔离及共享文件事实；不将其声称为该超时的已证实原因。Host Key、认证和其他协议默认值不变。

## 真实 Linux 验收

运行入口为 `tests/run-linux-acceptance.ps1`。`All` 顺序执行三个 exact 用例；每个单独限时 600 秒。可使用 `Deployment`、`Retention`、`AutomaticRetention` 分别重跑，不把零匹配或默认忽略算作通过。

| 用例 | 范围与证据 |
| --- | --- |
| Deployment | 单/多 Component 发布、历史/未部署回滚、HTTP 失败补偿、取消、库存/审计及只读对账；旧客户端通过 496.69 秒，更新后客户端通过 495.63 秒 |
| Retention | 四个生产创建的版本，Driver 测试策略保留 2 个；精确删除、权限导致目录已删/压缩包仍在、恢复权限后按新库存重试；先通过 169.39 秒，更新后客户端通过 175.57 秒 |
| AutomaticRetention | 六次经正式应用流程的测试发布，默认保留 5 个；首版两路径删除、保留包及本地成功清理意图全部验证，通过 182.60 秒 |

直接 Driver 用例在非 root `deploy` 账号下执行，先将准确 archives 目录改为不可写；在检查结果前恢复权限。快照验证 current、受保护 payload、Marker、metadata 和临时哨兵不变。此用例证明 Driver 行为，不冒充应用默认策略端到端验收。

默认策略用例的六个测试版本均经正式应用的构建、打包、上传和激活流程，目标始终是一次性夹具。检查保留包时使用每次执行真实保存的不可变包记录，不补造归档或历史；第六次只有一条准确指向首版的成功清理意图。第五版有契约健康记录，但此用例未配置 HTTP/systemd 探针；“最新五版之外的上一健康版本保护”由规划测试覆盖，真实业务健康验证沿用独立 M1 用例。

首次 Retention 尝试在第三次准备部署的激活阶段失败，尚未进入清理，不计为通过；已增强失败报告，后续两轮成功。不将未证实的首次失败原因归咎于 TCP 缓冲。部署中的正常失败/取消及预期清理权限失败是用例断言，不是套件失败。

通过的 Retention 运行标记为 `1bce0415ace74c129fd749e627031421`；顺序 Deployment/Retention 运行标记为 `de53830fc0034e5882ee807ac1522bea`；更新后客户端 Deployment 运行标记为 `c21325cb4cdb4f408aea31affca0304a`；AutomaticRetention 运行标记为 `781a235732c24dce8156f07ea5c7513c`。三个用例分别取得最终生产代码的证据，未将不同阶段的两例运行冒充一次最终 `All` 三例执行。Runner 退出码均为 0，额外只读检查确认各自容器、镜像标签和临时密钥目录已不存在。容器无特权、SSH 仅随机回环端口、只挂载临时公钥；不读取生产 Destination 或业务配置。普通 Docker 构建缓存允许保留。

## 资源预算与边界

每类本地证据最多 4,096 行/4 MiB；每 Component 最多规划 16 个候选。库存及单候选各 180 秒、整轮 600 秒。Linux 的连接/检查/两个路径命令/最终观察总预算保守为 175 秒；服务器单路径 25 秒加 2 秒终止宽限。剩余预算不足不启动删除；已开始的路径不被用户取消直接抛弃。

脚本固定目录/文件描述符，扫描最多 4,096 节点、64 KiB、4 GiB，拒绝 payload 符号链接、特殊文件和候选内挂载点。Marker、manifest 和压缩包必须各只有一个硬链接；普通 payload 硬链接只在候选目录内解除。无锁，不承诺对并发管理员替换目录/挂载的原子防护。检查异常或超限不启动删除；执行中失败保留逐路径事实，不扩大删除范围。

本轮 WSL Rust 工具链、缓存和构建输出使用独立临时目录。确认构建/测试进程结束并核对路径及所有者后，已删除约 4.8 GiB 可重新生成的数据；用户默认 Rust 仍为 1.84.1，未修改。真实 systemd、TUI 启动/退出沿用各自 M1 记录，本轮不声明 macOS、最低 Rust 1.88 或完整 QA-01 矩阵通过。完整历史、回滚与恢复管理页属于下一工作包 `TUI-MGT-01`。
