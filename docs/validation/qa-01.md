# QA-01 平台与 SSH 发行候选验证

日期：2026-09-05。状态：候选实现、独立审查及源码提交 `0b59f8f` 的 Windows 全量、release ConPTY 与真实 OpenSSH 门禁完成；stable 三平台、原生 Linux/macOS live gate 与 Rust 1.88 三平台 CI 尚未取得证据。因此 QA-01、M4 和完整 MVP **尚未验收**。

## 候选范围

- GitHub Actions 固定运行 Windows 2022 GNU、Ubuntu 22.04 GNU 和 macOS 15 arm64。stable 执行格式、严格 Clippy、全测试、release 构建与 TUI 性能门禁；Linux/macOS stable job 另执行原生 OpenSSH 门禁，Windows live gate 由需要已有系统 Agent 的显式 runner 提供。最低 Rust 1.88 执行全测试、release 构建和准确二进制 smoke。
- `platform_smoke` 在 PTY/ConPTY 中运行工作流刚构建的 release 二进制，验证 `q` 和空闲时收到 Ctrl+C 字节后再按 `q` 均正常退出。Unix 比较 termios 并要求完整的 alternate-screen/cursor 顺序；Windows 检查可观察的 cursor 恢复，只有 ConPTY 暴露 alternate-screen 字节时才要求其成对且有序。
- `linux_ssh_release_gate` 使用不同的 IdentityFile/Agent Key 和两个独立 Host Key，覆盖严格轮换拒绝、SFTP 成功/取消与远端命令取消。Windows、Linux 和 macOS runner 分别负责隔离、时限、所有权与清理。
- SSH 连接改为一个绝对总期限及固定阶段诊断。支持契约将 IdentityFile 限定为 1 MiB 内的本地普通文件；实现拒绝最终 link/reparse、特殊文件及明显的 Windows UNC/device 路径，但不声称可识别映射盘、网络挂载或父级 junction。进程级单飞 OS 线程隔离可能阻塞的读取；远端命令取消/超时在独立一秒窗口内尝试确认结果和终止 channel。

## 未完成门禁与发行结论

必须在拟验收提交取得 stable 三平台全部 CI 门禁、Rust 1.88 三平台测试/构建/smoke，以及 Linux/macOS 原生 OpenSSH live gate。若拟验收提交相对上述 Windows 证据提交仅修改文档，须核对代码、测试、依赖和工作流无差异，才能沿用该本地证据；执行相关文件有变化则重新验证。Windows 外部 OpenSSH 是单独显式运行，不冒充 CI job。CI 工具链只安装在 GitHub 的一次性 runner，不改变开发机或 WSL。

TUI-MGT-01 的早期间歇 SSH 超时和另一次 unknown-current 仍没有已证实根因。本候选将连接预算拆成 TCP、握手/Host Key、IdentityFile、Agent 和认证阶段，并加固取消与 runner 诊断；后续成功只能说明未复现，不能写成根因已修复。IdentityFile 的单飞线程也有明确边界：Rust 无法强杀永久阻塞的 OS 线程，极端情况下后续文件 Key 尝试会超时，进程退出后恢复。

在上述 CI 结果全部通过并记录前，不标注 Windows、Linux 或 macOS 的正式支持等级，也不开始 `QA-02`。
