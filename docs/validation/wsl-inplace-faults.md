## WSL 结果

Ubuntu-22.04 / Python 3.10.12，普通用户、Linux 临时目录。执行命令见 [测试指南](../../tests/README.md#wsl-publisher-fault-checks)。基础 16 项先单独通过，再由扩展套件运行这 16 项与 5 项新故障检查，合计 **21 项通过**，无跳过；不能把两轮重复基础测试当成额外覆盖。

| 故障 | 实际注入与结果 |
| --- | --- |
| 上一版压缩失败 | 临时元数据目录撤销写权限；真实权限拒绝，原应用不变 |
| 发布中途写入失败 | 子进程第二个应用文件替换抛出 EIO；第一个已更新、第二个未改，记录 publish-failed 后可恢复完整上一版 |
| 状态记录失败 | 状态文件替换抛出 EIO；不开始应用文件替换，保留失败现场 |
| 发布进程中断 | 第二个文件替换前真实 SIGKILL；退出 -9，混合文件状态不伪装成功，拒绝盲目观察结论、回滚或新发布 |
| 恢复过程写入失败 | 恢复第二个文件时 EIO；保留上一版包与不确定状态，拒绝重复恢复 |

基础用例同时覆盖上传/上一版包损坏、路径遍历、硬链接、外部修改、身份/版本错配、服务阶段未知、旧静态资源移除、仅保留上一版及按操作身份丢弃上传。扩展套件每例验证应用范围之外的 runtime 哨兵内容不变。临时目录由测试清理；权限在 finally 中恢复；SIGKILL 仅发送给测试自己启动的发布器子进程。

## 证据边界与剩余项

WSL 检查执行源码中随产品嵌入的 Python 发布器，新增故障通过 runpy 执行其真实入口和异常处理。它不是 Windows exe 经 SSH 的整条部署流程，也没有启动真实 systemd/PM2。服务非零退出和缺失退出状态本轮由 Windows 生产 Driver 的回环协议测试模拟验证，不能称为真实服务验收。

没有连接业务项目、读取保存凭据、修改 SSH/sudoers/systemd 配置或安装工具。未填满 WSL/主机磁盘、未强制关闭 WSL；EIO 注入与进程 SIGKILL 不证明断电后的持久性。真实服务健康失败、SSH 断连、客户端强制结束及多组件真实恢复仍需独立的端到端测试环境和用例；本记录不标记整个异常覆盖或 MVP 已完成。
